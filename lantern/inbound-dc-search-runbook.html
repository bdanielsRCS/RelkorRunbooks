📖 How to use this runbook

  1. Work the test cards top-to-bottom — each one targets a specific fix from the Jira story (LC-591) or a regression check.
  2. Each card has numbered steps, a green "Expected" callout, and three result buttons: ✓ pass, ✕ fail, reset. Clicking pass/fail highlights the card and updates the summary counter at the bottom.
  3. State is saved in your browser — close the tab and come back later, your check-marks and notes will still be there.
  4. If a test fails, drop the exact error text into its Notes textarea and the Bug report pad at the bottom. The triage flowchart in §⑤ maps common errors to likely causes.
  5. The "Mid-test patches" panel below lists everything that was fixed during earlier test passes — useful context but not required reading if you just want to run the tests.

🛠 Mid-test patches shipped live in latStag

Bugs identified during earlier test passes, already deployed to staging. Hard-refresh Flow Builder (⌘⇧R) before re-testing.

  • Datatable keyField rejected by Flow Builder — server silently rewrote the Id reference to null__NotFound on save. DMOs need a real __c field as the row key. Switched to surgeryPlusMemberId__c. → fixed before Test 1
  • NavigatetoAccount failed when picking an existing member — used firstSelectedRow.X18_Digit_ID__c, but datatables only expose fields declared in columnReferences, so the value was null. Switched to .Id. → fixed during Test 5
  • "Results found?" decision routed wrong on no-match — when only one search lookup fires (decision branching), the others stay null. The Add_All assignment can't merge null collections, so Count_Results aggregated null → returned null → null < 1 evaluated false → empty Results Table rendered instead of the "No one matches" screen. Added an IsNull OR LessThan 1 condition. → fixed during Test 4
  • First Name column header showed raw firstName — set hasCustomHeaderLabel: true. Cosmetic. → fixed alongside Test 4
  • Test 5 still failing — firstSelectedRow.Id rejected too. Datatable rows only expose fields declared in columnReferences; the keyField doesn't count. Added Id to MatchingActiveMembers.columnReferences. → v1.2 patch
  • Test 4 still failing — Count = 1 with one null row. Flow's Add operator treats a null source as a single null entry, polluting the merged collection. Re-introduced a Filter (Filter_Out_Null_Rows, surgeryPlusMemberId__c IsNull = false) between Add_All and Count_Results, and rebound the datatable + Count to read from the Filter output. → v1.2 patch
  • MatchingActiveMembers columns shifted — Account Name displayed the Id. Datatable maps display columns to columnReferences by position, not apiName. Adding Id at index 0 pushed every visible column off by one. Moved Id to the end of the field list so display columns align again. → v1.3 patch
  • Hardcoded RecordType IDs replaced with lookups. Surgery CarePlan RT (012cV000000VYn1QAG) and Member Person Account RT (012cV000000Q0KjQAK) were hardcoded — would silently break on prod deploy. Added two Get RecordType lookups at flow start (by SObjectType + DeveloperName: Account/Member, CarePlan/Surgery), now referenced as Get_Member_Account_RT.Id and Get_Surgery_CarePlan_RT.Id. → v1.4 (#3)
  • Input validation gating Next on Search Criteria screen. Added a validationRule on the EmployeeNumber field that allows submission only if the user picked a row from the top tables OR populated at least one search field. Prevents wasted "no match" runs from empty submits. → v1.4 (#9)
  • Search architecture overhauled to match the LC-591 search matrix. Jira LC-591 specifies 4 valid combos: First+Last Name, Last Name+DOB, Last Name+Client, Employee#+Client. Replaced the priority-based single-field branching (which ignored additional inputs after the first match) with 4 focused Get Records lookups, one per combo, driven by a new What_Combo_Is_Valid decision. Each branch assigns its result to a shared var_DC_SearchResults collection. Eliminated the null-pollution issue from the old Add_All pattern and deleted the Filter_Out_Null_Rows workaround. Validation rule also updated to enforce the 4-combo matrix. → v1.5 matrix restructure

⚠️ About debug-mode navigation: c:navigateToRecord doesn't actually navigate when you run from Flow Builder Debug — there's no Lightning page context. The action shows as completed in the left rail, no error → that's pass. Real navigation only happens on a live record-page run.

⑤ If something breaks

Triage flow.

Step 1 — Read the actual error.

In Debug, scroll the left rail to find the red "Error element …" entry. Note the element name AND the exact message.

Step 2 — Check what kind of error.
  • "Invalid reference … null__NotFound" → a field reference was rewritten by the server because it's not valid on the target object. Same root cause as the keyField bug we hit. Tell me the element + field.
  • "FIELD_CUSTOM_VALIDATION_EXCEPTION" → an org validation rule blocked a record create. Probably the hardcoded test data hitting a rule. Note which rule.
  • "You don't have access" → the running user lacks read on a DMO field or object. Check Profile/PermSet.
  • "DUPLICATE_VALUE" → trying to create a Lead/Account that already exists. Re-test with different inputs or clean up.
Step 3 — Send back.

Screenshot the Debug rail (especially the failing element + the value of every variable at that point). Drop it in the chat — fastest path to a fix.
