⚠️ Before you start

  • Test in UAT (Full Copy) — never run these in Production
  • Sign in as a user with both ARR and ZB access — the simplest path is a Sandbox Admin or someone in ARR_All_Users AND a ZB group. If you don't have a hybrid user, you'll need to switch logins between ARR and ZB tests.
  • Have an existing ARR encounter ready — pick one for Northwestern Medicine if possible (they have ARR Split Commission enabled — needed for TH-507 cap testing)
  • Have an existing ZB encounter ready — for the cross-LOB negative tests
  • Click each test card to expand, follow the steps, then mark Pass or Fail. Your progress is saved in this browser.
  • Found a bug? Click Fail and add notes — those notes save with the card.

TH-477 ARR-specific fields on Encounter & Encounter Payor

Foundation story. Adds 8 new fields to Encounter (Case), 3 new formula fields to Encounter Payor, plus page-layout placements per AC. Includes a helper formula Has_Encounter_Payors__c used by TH-583's button visibility.

1
Verify new Encounter (Case) fields are created
Not started
Setup: Open any ARR Encounter record in UAT. Use the Lightning App's Encounter list, or paste a known ARR Case Id into the URL.
Action: Click the gear icon → Edit Page (or just edit the record from the page directly). Verify each of the following fields is now visible/editable on the page:
  • Placement Date (DateTime)
  • Secondary Payor (Imported) (Text)
  • Tertiary Payor (Imported) (Text)
  • Primary Payor Balance (Imported) (Currency)
  • Secondary Payor Balance (Imported) (Currency)
  • Tertiary Payor Balance (Imported) (Currency)
  • Client Epic Work Queue (Text 80)
Expected: All 7 fields exist on the Encounter object and are visible on the ARR Lightning Record Page. Try setting values on each — they should save.
2
Verify section placements on the ARR Lightning Record Page
Not started
Setup: Open an ARR Encounter record.
Action: Confirm each field appears in the named section on the page:
  • Encounter Overview section: Placement Date, Client Epic Work Queue
  • Imported Payor Details section: Secondary Payor (Imported), Tertiary Payor (Imported), Primary Payor Balance (Imported), Secondary Payor Balance (Imported), Tertiary Payor Balance (Imported)
Expected: Each field appears in the correct section, no duplicates.
3
Verify Encounter Payor formula fields
Not started
Setup: Open an ARR Encounter that has at least one Encounter Payor with a Payor Type set (Primary/Secondary/Tertiary). If none, navigate to the Encounter Payor record directly.
Action: On the Encounter Payor record, in the Encounter Payor Details section, confirm:
  • Encounter Payor Imp. Balance — pulls the right imported balance from the parent Encounter based on Payor Type (Primary → Primary_Payor_Balance_Imported, Secondary → Secondary, Tertiary → Tertiary)
  • Encounter Payor Net Balance — calculates as Imp Balance − Total Payments − Total Adjustments + Total Transfers
  • Encounter Payor Financial Class — displays the Financial Class from the Account selected in the Payor Name lookup
Expected: All three formula fields show calculated values. Change a Total Payments amount and Net Balance recalculates.
4
Verify Encounter Payor Related List on ARR page shows new columns
Not started
Setup: Open an ARR Encounter with one or more Encounter Payors.
Action: Scroll to the Encounter Payors related list. Verify the new columns are present in the correct order:
  • Encounter Payor Imp. Balance appears to the left of Total Payments
  • Encounter Payor Net Balance appears after Total Transfers
Expected: Both columns visible in the related list with correct values.

TH-507 ARR contingency-rate cap enforcement

Existing Flow already stamps rate. Extended Flow now caps total Invoice Line Item Amount across Payment FAs at the Client-level Cap (only when Split Commission is enabled). FLS restricts Contingency Rate & ILI to Supervisors+.

Best test client: Northwestern Medicine in UAT — has Split Commission enabled with Cap_1 = $3,000, Cap_2 = $5,000, Rate_1 = 6%, Rate_2 = 9%, Days Threshold = 90.
1
First Payment FA: rate stamps from Account configuration
Not started
Setup: Find an ARR Encounter for Northwestern Medicine where (Date Assigned − Discharge Date) ≤ 90. Confirm no Payment FAs exist yet (or pick a fresh test encounter).
Action: Create a new Financial Activity on this encounter:
  • Transaction Type = Payment
  • Qualified Amount = $1,000
  • Save
Expected:
  • Contingency Rate = 6% (Rate_1, since days ≤ 90)
  • Invoice Line Item Amount = $60.00 (6% × $1,000)
2
Cap enforcement: rate adjusts down on FA that would exceed Cap
Not started
Setup: Same encounter from Test 1. Create more Payment FAs to push the cumulative ILI close to Cap_1 ($3,000). For example, make several FAs at Qualified Amount = $10,000 (each ILI = $600 at 6%) until total ILI is just under $3,000.
Action: Create one more Payment FA with a Qualified Amount that would, at the natural 6% rate, push total ILI over $3,000.
Expected: The new FA's Contingency Rate is adjusted DOWN so that its Invoice Line Item Amount equals exactly (Cap_1 − sum of existing Payment ILIs). Total ILI across all Payment FAs = $3,000 exactly.
3
Cap reached: subsequent FA gets rate = 0
Not started
Setup: Same encounter from Test 2 — total ILI now = Cap.
Action: Create one more Payment FA with any Qualified Amount.
Expected: Contingency Rate = 0, Invoice Line Item Amount = $0.00.
4
Field visibility — Contingency Rate & ILI Amount visible only to Supervisors+
Not started
Setup: Sign in as a non-supervisor user (Auditor or Collector level).
Action: Open an FA record. Look for Contingency Rate and Invoice Line Item Amount.
Expected: Both fields are NOT visible to this user. Then sign in as a Supervisor user and confirm both fields ARE visible.
