Task Description & Reference Documentation

Current State

  • Case OWD is Private — no user sees any Case by default
  • ZB workflow already restricts auditors from seeing encounters with Status Code = Unassigned (existing behavior this story replicates for ARR)
  • ARR encounters imported into the system currently have no queue-based workflow — once sharing rules (TH-486) grant access, all encounters for a client are visible to that client's group regardless of assignment status

Ideal State

  • Unassigned ARR encounters are invisible to collectors — they cannot see them in list views, search results, or via direct link
  • Only ARR supervisors can see unassigned encounters and assign them to collectors
  • Once a supervisor assigns an encounter to a collector, the collector gains visibility
  • This mirrors the existing ZB restriction where auditors cannot see unassigned encounters

Reference

  • Implementation stories: Titan-Health-R3-Implementation-Stories.html (Story 2)
  • Sharing architecture review transcript: Titan Health Sharing Arch Review.txt
  • Dependency: TH-486 must be implemented first (public groups and sharing rules)

Technical Configuration Notes

Prerequisites

1. Create ARR Queues

Create 2 queues in Setup > Queues:

Queue Label API Name Supported Objects Queue Members
ARR - Unassigned ARR_Unassigned Case ARR - Supervisors group only
ARR - Collections ARR_Collections Case ARR - Supervisors group only
  • Only the ARR - Supervisors public group should be a queue member — do NOT add individual collectors
  • Uncheck "Send Email to Members" (optional per notification preferences)

How It Works

  1. Encounters are imported and assigned to the ARR - Unassigned queue
  2. Queue ownership + Private OWD = only queue members (supervisors) can see them
  3. Supervisor reviews and assigns encounter to a collector (changes owner from queue to user)
  4. Once user-owned, the collector gains visibility through their client-specific sharing rule (TH-486)
  5. Encounters moved to collections go to the ARR - Collections queue — again only visible to supervisors until reassigned

Collectors never see the queue and never see unassigned encounters. They only see encounters explicitly assigned to them (or to other users in their client group via sharing rules).

Technical Acceptance Criteria

Validation Queries

As an ARR Collector — this should return 0:

SELECT COUNT() FROM Case WHERE LOB__c = 'ARR' AND Owner.Type = 'Queue'

As an ARR Supervisor — this should return > 0:

SELECT COUNT() FROM Case WHERE LOB__c = 'ARR' AND Owner.Type = 'Queue'

Metadata Components for Deployment

  • 2 Queues (ARR_Unassigned, ARR_Collections)
  • Queue membership configuration (ARR - Supervisors group)
