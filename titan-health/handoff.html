3. Architecture & Conventions

3.1 Two LOBs in one org

Both LOBs use the same Case object. They're separated by Record Type (Accounts_Receivable_Recovery_ARR vs Zero_Balance_ZB) and routed through different queues, groups, permissions, and Lightning pages:

  • Titan_Health_Case_Record_Page — generic
  • Titan_Health_ARR_Encounter_Record_Page — ARR-specific (used in UAT/Prod; Dev uses generic)
  • Titan_Health_Encounter_Payor_Record_Page — for the EP child object

The two LOBs never share data through sharing-rule layer. A user only sees ARR data if they're in an ARR group; only sees ZB data if they're in a ZB group. Hybrid users belong to both.

3.2 Sharing model — Case is Private OWD

Case OWD = Private. Access comes only from: (a) record ownership, (b) Case Team membership, (c) one of the 7 criteria-based sharing rules:

Rule Who When Access
ARR_Client_Christus_Access ARR Christus team Christus ARR encounter past Newly Unassigned Edit
ARR_Client_NWM_Access ARR NWM team NWM ARR encounter past Newly Unassigned Edit
ARR_Supervisor_CHS_Newly_Unassigned_Access ARR Christus supervisors Christus ARR encounter is Newly Unassigned Edit
ARR_Supervisor_NWM_Newly_Unassigned_Access ARR NWM supervisors NWM ARR encounter is Newly Unassigned Edit
ZB_Encounters_Read_Edit_Access ZB Edit team ZB encounter past Unassigned Edit
ZB_Encounters_Read_Only_Access ZB Read-Only team ZB encounter past Unassigned Read
ZB_Supervisor_Unassigned_Access ZB supervisors ZB encounter is Unassigned Edit

Detail objects (Encounter_Payor__c, Encounter_Code_Change__c, Document_Request__c, Financial_Activity__c) use Controlled By Parent sharing — they automatically inherit Case's access. Never set up sharing on these directly.

3.3 Permission architecture (layered)

  1. Object × Persona perm sets (~54): Titan_Health_<Object>_<Persona> — generic across BUs.
  2. Titan_Health_SPECIAL_* perm sets (~14): elevated permissions assigned only when needed.
  3. BU-specific perm sets (4): ARR_Admin, ARR_Collector_Base, ARR_Supervisor_Elevated, ZB_Collector_Base.
  4. Permission Set Groups (22): admin assigns one PSG per user role.

3.4 Picklist conventions

  • GVS-backed (restricted) picklists: Status_Code__c, Adjustment_Codes__c use Status_Code_GVS and Adjustment_Codes_GVS GlobalValueSets. Adding values is a 2-step deploy — add to the GVS, and add to the consuming Record Type's <picklistValues> block (UAT's record types have explicit picklistValues blocks; new GVS values are NOT auto-allowed).
  • ARR-prefix convention: values intended for ARR records are prefixed ARR -. There's currently no Record-Type filter actually enforcing this — the prefix is the convention. (If strict enforcement is needed later, that's a separate change.)

3.5 Encounter Guidance

Encounter_Guidance__c records drive automated routing on Status Code change. Each record is keyed on Status Code + Record Type and specifies:

  • Case_Status_Category__c (inline picklist — different from Case's own Status Code Category!)
  • Days_to_Follow_Up__c
  • Expected_Record_Owner__c — picklist of owner names that downstream automation maps to actual queues (e.g., "Collections" → ARR_Collections queue)
  • Guidance_Details__c (required)
  • Guidance_Field_Type__c (required)

UAT has 23 ARR Encounter Guidance records today (driven mostly by R3 Sprint 2's TH-584 work).

6. Operational Runbook

6.1 SF CLI essentials

# Always update first
sf update

# List orgs & confirm aliases
sf org list

# Open an org
sf org open --target-org titan-full

# Pull metadata inventory of one type
sf org list metadata --metadata-type CustomField --target-org titan-full --json

# Describe an object
sf sobject describe --sobject Case --target-org titan-full --json

# Retrieve via manifest
sf project retrieve start --manifest path/to/package.xml --target-org titan-full

# Deploy a directory (dry-run first)
sf project deploy start --source-dir force-app --target-org titan-full --dry-run --wait 10
sf project deploy start --source-dir force-app --target-org titan-full --wait 15

# Deploy with destructive changes (e.g. xD field deletion pattern)
sf project deploy start \
  --manifest deploy-package.xml \
  --post-destructive-changes destructive/destructiveChanges.xml \
  --target-org titan-full --wait 15

# Run all Apex tests after a deploy
sf apex run test --target-org titan-full --result-format human

6.2 Deployment workflow

  1. Develop in titan-dev (or feature branch retrieve-and-edit).
  2. Log change in docs/CHANGE-LOG.md before pushing to UAT.
  3. Dry-run against titan-full (--dry-run).
  4. Deploy to titan-full (UAT). Verify smoke tests + UAT acceptance.
  5. Production cutover as a separate, scheduled event with the pre-cutover checklist (§7) executed in advance.

6.3 Org-discovery / re-baseline pattern

Per Relkor/CLAUDE.md "Always Verify Schema Before Assuming":

  1. Pull metadata inventories from each org (sf org list metadata --metadata-type X).
  2. Cache as JSON under metadata/snapshots/<alias>/.
  3. Diff against the source-of-truth org (UAT for this project).
  4. For any field/picklist value referenced in code or layouts, verify it exists in the TARGET org before deploy. Lesson learned: LOB__c was assumed prod-resident because it existed in Dev; turned out to be a scratch-org artifact.

6.4 Picklist deploy gotchas (learned in Sprint 2)

  • GVS values added to a GVS DO NOT automatically become available on Record Types that have explicit picklistValues blocks. You must update the Record Type metadata too.
  • Inactive GVS values cannot be referenced in picklistValues blocks — filter them out when generating XML programmatically.
  • Special characters in picklist values (commas, etc.) are tricky to encode in picklistValues — easiest workaround when feasible is to simply exclude such values from a Record Type's allowed list if they aren't used by that RT.
  • GVS deploy "Unchanged" warning (Status_Code_GVS__gvs returned from org, but not found in the local project) is a benign sf CLI quirk — the deploy actually works; verify via Tooling REST API rather than lastModifiedDate.

6.5 FlexiPage tricks

  • Visibility rules only support EQUAL and NOT_EQUAL for component visibility. To express "count > 0", create a boolean formula field (Has_X__c = Count__c > 0) and check EQUAL true.
  • Field-type column references in List Views: standard Case fields use CASES.<NAME> (e.g., CASES.SUBJECT); custom fields use the API name (Titan_Net_Balance__c); owner column is OWNER_NAME. Boolean filter values must be 1/0, not true/false.
  • Queue-bound List Views set <filterScope>Queue</filterScope> and <queue>QueueDevName</queue> (not Sharing settings).

6.6 Queue membership

The <queueMembers><publicGroups>X</publicGroups></queueMembers> block in a Queue's metadata XML may not actually create membership records at deploy time. After deploy, if the Queue has no members:

sf data create record --sobject GroupMember \
  --values "GroupId=<queue-id> UserOrGroupId=<group-id>" \
  --target-org titan-full

11. Glossary

Term What it means
ARR Accounts Receivable Resolution — new line of business in R3
ZB Zero Balance — existing line of business
LOB Line of Business
Encounter Patient encounter (medical visit) — represented as a Case record
Encounter Payor Insurance/payor relationship for an encounter — child of Case (Encounter_Payor__c)
OWD Org-Wide Default — platform's default access level. "Private" = only owner sees by default
Sharing Rule Automatically grants access to records meeting certain criteria
Permission Set / PSG Controls field/object/feature access; PSG bundles them
Public Group List of users/groups/roles used by sharing rules and queue membership
Queue Holding area for records awaiting assignment; can own records
Record Type Mechanism for distinguishing different kinds of the same object (e.g., ARR vs ZB Cases)
Case Team List of users granted access to a specific Case beyond what sharing rules grant
Schedulable Apex class running on a configurable schedule (cron-like)
Athena AWS's serverless analytics database — where archived encounters land
CMDT Custom Metadata Type — configuration stored as metadata
GVS Global Value Set — picklist values shared across multiple fields
FlexiPage Lightning Record Page metadata format
